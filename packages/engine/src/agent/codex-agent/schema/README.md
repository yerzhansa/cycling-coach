# Vendored `codex app-server` JSON Schemas

These files are the contract-of-record for the wire shapes the `codex-agent`
lane sends and consumes. They are generated by the pinned `codex` binary, not
hand-written, and `pnpm check:codex-schema` (`tools/check-codex-schema.ts`)
asserts that every method and every params field the client emits — plus every
field it reads back — exists here. Editing a file by hand defeats the gate.

## Pin

`CODEX_SCHEMA_PIN` in `../version.ts` records the exact upstream version these
were generated from. The lane's hard floor is `CODEX_VERSION_FLOOR`; a binary
newer than the pin runs (the reader is tolerant) and logs one drift line.

## Regenerating on a pin bump

```sh
TMP=$(mktemp -d)
codex app-server generate-json-schema --out "$TMP"
```

Then copy forward **only** the files already present in this directory — the
generator emits ~275 types and vendoring all of them produces a diff nobody can
review. The current selection is: the `initialize` pair; the `thread/start`,
`turn/start`, `turn/interrupt`, `account/read`, `model/list` and `config/read`
params/response pairs; the five server-to-client approval params/response pairs;
and the twelve notification types the lane consumes. `Turn`, `ThreadItem` and
`TokenUsageBreakdown` arrive transitively inside those files' `definitions`
blocks.

## Key-sort canonicalization (required)

The generator's key order is **not** stable against the order produced by a
round-trip through `JSON.parse`/`JSON.stringify`, so a byte compare reports
DIFFERS even when the two are semantically identical. Every file here is written
with object keys recursively sorted, two-space indent, and a trailing newline:

```js
const canon = (v) =>
  Array.isArray(v)
    ? v.map(canon)
    : v && typeof v === "object"
      ? Object.fromEntries(
          Object.keys(v)
            .sort()
            .map((k) => [k, canon(v[k])]),
        )
      : v;
fs.writeFileSync(dest, JSON.stringify(canon(JSON.parse(src)), null, 2) + "\n");
```

Apply the same canonicalization to the freshly generated files before diffing,
or the gate fires on every run.

Then run `pnpm exec oxfmt packages/engine/src/agent/codex-agent/schema` over the
result. The repo formatter collapses short arrays onto one line, so without this
step a later `pnpm fmt` would rewrite every vendored file and the next pin bump
would diff against a moved baseline.

## Upstream reads

Read upstream source at the tag that matches the pin, never at `HEAD` — the
upstream tree drifts ahead with methods and fields that do not exist at the
pinned version.
